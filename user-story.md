# User Story

## Поиск текущей погоды
Как пользователь, я хочу ввести название города и получить текущую погоду, чтобы узнать температуру, влажность и скорость ветра.
Приоритет: высокий.


## Просмотр прогноза на 3 дня
Как пользователь, я хочу видеть прогноз погоды на ближайшие три дня, чтобы планировать свои дела.
Приоритет: высокий.


## Получение рекомендаций
Как пользователь, я хочу получать рекомендации по одежде и поведению в зависимости от погоды, чтобы подготовиться к условиям на улице.
Приоритет: средний.


## Использование кэша
Как пользователь, я хочу получать ранее загруженные данные из кэша, чтобы быстрее увидеть погоду при повторном поиске.
Приоритет: средний.


## Обработка ошибок
Как пользователь, я хочу получать понятные сообщения об ошибках, если город не найден или отсутствует интернет, чтобы понимать, что произошло.
Приоритет: высокий.

# Use Case

## UC-01. Запуск приложения

 **Актор**  Пользователь 
 **Предусловия**  Python и необходимые библиотеки установлены 
 **Триггер**  Пользователь запускает файл `main.py` 

### Основной сценарий

1. Пользователь запускает приложение.
2. Приложение записывает событие запуска в `app.log`.
3. Открывается графическое окно приложения.
4. В поле поиска отображается город по умолчанию — Москва.

### Результат

Приложение готово к работе.

---

## UC-02. Ввод названия города

 **Актор**  Пользователь 
 **Предусловия**  Приложение запущено 
 **Триггер**  Пользователь вводит город в поисковое поле 

### Основной сценарий

1. Пользователь нажимает на поле ввода.
2. Вводит название города.
3. Нажимает кнопку **«Узнать»** или клавишу `Enter`.
4. Приложение начинает поиск погоды.

### Альтернативный сценарий

- Если поле пустое, приложение показывает предупреждение: **«Введите название города»**.

### Результат

Приложение получает название города для дальнейшего поиска.

---

## UC-03. Поиск координат города

**Актор**  Система 
 **Предусловия** Пользователь ввёл название города 
 **Используемый сервис**  Geocoding API Open-Meteo 

### Основной сценарий

1. Приложение отправляет название города в сервис геокодинга.
2. Сервис выполняет поиск города.
3. Приложение получает широту, долготу, название города и страну.
4. Координаты используются для запроса погодных данных.

### Альтернативный сценарий

- Если город не найден, приложение создаёт ошибку с сообщением: **«Город не найден»**.

### Результат

Координаты города получены.

---

## UC-04. Получение текущей погоды

**Актор**  Система 
 **Предусловия**  Координаты города успешно получены 
 **Используемый сервис**  Forecast API Open-Meteo 

### Основной сценарий

1. Приложение отправляет широту и долготу в API прогноза.
2. API возвращает текущие погодные данные.
3. Приложение получает температуру и ощущаемую температуру.
4. Приложение получает влажность, скорость ветра, осадки и погодный код.

### Результат

Текущие погодные данные получены и готовы к отображению.

---

## UC-05. Просмотр текущей погоды

**Актор**  Пользователь 
 **Предусловия**  Текущая погода успешно загружена 
 **Триггер**  Завершение запроса к API или загрузка данных из кэша 

### Основной сценарий

1. Приложение отображает название города и страну.
2. Показывает описание погодных условий.
3. Показывает текущую температуру.
4. Показывает ощущаемую температуру.
5. Показывает относительную влажность.
6. Показывает скорость ветра.

### Результат

Пользователь видит текущую погоду выбранного города.

---

## UC-06. Просмотр прогноза на 3 дня

**Актор**  Пользователь 
**Предусловия**  Прогноз успешно получен от API 

### Основной сценарий

1. Приложение получает прогноз на три дня.
2. Отображает дату каждого дня.
3. Показывает минимальную температуру.
4. Показывает максимальную температуру.
5. Показывает описание погодных условий.
6. Показывает вероятность осадков.

### Результат

Пользователь видит прогноз погоды на ближайшие три дня.

---

## UC-07. Получение рекомендаций

**Актор**  Пользователь 
**Предусловия**  Текущая погода и прогноз загружены 

### Основной сценарий

1. Приложение анализирует температуру.
2. Проверяет вероятность осадков.
3. Проверяет наличие дождя.
4. Проверяет скорость ветра.
5. Формирует текстовые рекомендации.
6. Показывает рекомендации пользователю.

### Примеры рекомендаций

- Взять зонт при высокой вероятности осадков.
- Надеть тёплую одежду при отрицательной температуре.
- Надеть куртку в прохладную погоду.
- Взять воду и головной убор в жаркую погоду.
- Соблюдать осторожность при сильном ветре.

### Результат

Пользователь получает практические рекомендации в зависимости от погоды.

---

## UC-08. Получение данных из кэша

**Актор**  Система 
**Предусловия**  Данные по городу ранее были сохранены в SQLite 
 **Срок действия кэша**  30 минут 

### Основной сценарий

1. Пользователь повторно запрашивает погоду для города.
2. Приложение проверяет наличие записи в кэше.
3. Приложение проверяет возраст сохранённых данных.
4. Если данные младше 30 минут, приложение загружает их из кэша.
5. Данные отображаются пользователю.

### Результат

Погода загружается быстрее без повторного обращения к API.

---

## UC-09. Обновление устаревших данных

**Актор**  Система 
 **Предусловия**  Данные в кэше старше 30 минут 
 **Триггер**  Пользователь повторно запрашивает погоду 

### Основной сценарий

1. Приложение обнаруживает устаревшие данные.
2. Отправляет новый запрос к API геокодинга.
3. Получает актуальные координаты города.
4. Запрашивает свежий прогноз погоды.
5. Сохраняет новые данные в SQLite.
6. Отображает обновлённую информацию пользователю.

### Результат

Кэш обновлён, а пользователь видит актуальные погодные данные.

---

## UC-10. Обработка ошибок приложения

**Актор**  Пользователь 
 **Предусловия**  Пользователь выполняет поиск погоды 
 **Журналирование**  Ошибки записываются в `app.log` 

### Основной сценарий

1. Приложение выполняет запрос к API.
2. Возникает ошибка.
3. Приложение определяет тип ошибки.
4. Ошибка записывается в журнал.
5. Пользователю показывается понятное сообщение.
6. В строке состояния отображается статус ошибки.

### Результат

Пользователь понимает причину ошибки, а разработчик может найти подробности в файле `app.log`.
